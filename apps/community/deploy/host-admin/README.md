# Owner-only host administrator broker

This optional Linux service executes commands as **root on the OCI host** for the
explicitly configured application account. It is intended for the owner's own
sessions. It does not grant this permission to every site administrator, invited
user, shared-room participant, desktop container, or browser. Application code
must derive the actor from the authenticated message sender, never from text
generated by a model or a caller-supplied user ID.

The broker listens only on a Unix socket. The trusted application backend is
its only client. A backend compromise consequently crosses the host trust
boundary; this service deliberately grants host administration, not a sandbox.
Do not mount the socket into desktop, browser, gateway, build, or user containers.

## Installation

Install `service.py` as root-owned, non-writable application code at
`/usr/local/lib/community-host-admin/service.py` and the systemd unit at
`/etc/systemd/system/community-host-admin.service`.

Create `/etc/openclaw/host-admin.json` as root with mode `0600`. Supply real
application user UUIDs from the private deployment database; do not commit them.

```json
{
  "user_ids": ["<owner application user UUID>"],
  "peer_uid": 1000,
  "socket_path": "/run/community-admin/admin.sock"
}
```

`peer_uid` must match the backend's **host-visible UID**, including any user
namespace mapping. Its primary/supplementary group must also permit access to
the socket. The socket is owned by root with group `peer_uid` and mode `0660`.
Peer identity is checked with Linux `SO_PEERCRED` on every request; headers do
not override it. The service fails closed on other platforms.

The supplied unit creates `/run/community-admin` and the private state directory
`/var/lib/community-host-admin`. If choosing another socket directory under
`/run`, provision a root-owned directory without group/other write access and
update the unit's runtime-directory configuration accordingly.

Enable/restart after configuration and the application integration are ready:

```sh
systemctl daemon-reload
systemctl enable --now community-host-admin.service
```

Mount the **directory** `/run/community-admin` into only the application backend,
not the socket inode (which is recreated when the service restarts). Keep this
an internal mount with no reverse-proxy route. The service has no TCP port and
never reads an application token, OCI key, or model key from the environment.
Configuration changes require restarting the service.

## HTTP contract

All routes require the configured Unix peer UID. `GET /health` returns:

```json
{"ok": true, "scope": "host-root"}
```

`POST /execute` accepts `Content-Type: application/json` and one explicit
`Content-Length`. Chunked bodies are rejected. Maximum body size is 100,000 bytes.

| Field | Validation |
| --- | --- |
| `requestId` | Required canonical lowercase nonzero UUID, new for each intended command |
| `userId` | Required canonical lowercase nonzero UUID, must match `user_ids` |
| `roomId` | Required canonical lowercase nonzero UUID for audit correlation |
| `command` | Required nonempty string, at most 16,000 characters, no NUL |
| `cwd` | Absolute path, default `/`, at most 4,096 characters, no NUL |
| `timeoutMs` | Integer 1,000–120,000, default 30,000 |

Unexpected JSON fields are rejected. The broker does not independently verify
room membership: that belongs to the backend, together with user authentication
and per-message owner gating. An owner being a room member must **never** grant
host execution to an invited member's message.

A completed invocation returns HTTP 200 even for a nonzero command exit status:

```json
{
  "requestId": "<same request UUID>",
  "scope": "host-root",
  "exitCode": 0,
  "stdout": "…",
  "stderr": "",
  "timedOut": false,
  "truncated": false
}
```

`stdout` plus `stderr` are capped at a combined 16,384 raw bytes and decoded as
UTF-8 with replacement. Additional output is drained and discarded, not written
to disk or journal. Timed-out commands have `exitCode: 124` and `timedOut: true`.
The broker launches `/bin/bash --noprofile --norc -lc` with fixed PATH, HOME,
USER, LOGNAME and LANG only. It does not inherit service secrets or source shell
profiles. Root commands can still intentionally read any host file.

Error statuses include 400 invalid request, 403 peer/actor denied, 409 request ID
already seen, 503 executor busy/unavailable. At most four commands run at once.
The backend must not retry automatically, including on 503, disconnect, timeout,
or an ambiguous response. A user-requested repeat is a new intended command and
requires a new UUID.

## Cancellation, persistence and audit

The service monitors the client connection while executing. Client disconnect or
deadline expiry sends TERM and then KILL to the command's process group. The
same cleanup runs on ordinary completion to remove lingering children. A daemon
which explicitly detaches into another session can escape a process-group
signal; root administration cannot safely be treated as untrusted execution.
Commands intended to keep running should use the host's service manager. On
broker stop/restart, systemd kills the entire service cgroup.

Request UUIDs are claimed durably **before** command launch in a root-only SQLite
database. They remain reserved for successes, failures, cancellation and unknown
outcomes, including after restart. Startup marks unfinished records interrupted;
it never resumes or replays them. Deleting this database also removes replay
protection and is not normal maintenance.

Only request/user/room IDs, timestamps, outcome, exit code, output-truncation flag
and duration are journaled. Neither commands nor output are persisted. The
database contains request IDs and outcome metadata only. The backend must apply
its own access control to results and avoid revealing host secrets in a shared
room; host permissions and permission to publish the output are separate.

## Tests

Run without sudo from the repository root:

```sh
python3 -m unittest discover -s apps/community/deploy/host-admin -v
```

Tests use temporary files and the current user's subprocesses. Linux peer
credentials are mocked at the HTTP boundary so the suite can run on macOS.
Tests exercise config permissions, peer/actor rejection, validation, bounded
output, empty inherited secrets, command failure, process-group timeout and
disconnect, HTTP health, durable replay rejection and metadata-only auditing.
Production deployment must additionally verify the actual backend host UID and
socket permissions, plus an owner request versus an invited-user request.
